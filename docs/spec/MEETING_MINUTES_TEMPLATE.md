# 議事録からタスク（タスク）を作る

議事録に書いた1行から、そのままタスクを作れる。転記の手間をなくすための仕組みで、
議事録の中でタスクを管理するものではない。作ると、議事録の行に「タスク作成済み」の印が付き、
押すとそのタスクへ移動できる。

作り方は2つある。**新しく書くときは A を使う。** B は前からある書き方で、そのまま動く。

---

## A. Wiki ページのリンクで作る（推奨・v1.1〜）

未チェックのチェックリスト行に、Wiki ページへのリンクが入っていれば候補になる。
新しい書き方を覚える必要はなく、本文にリンクを差し込む操作（「/」→ Wiki）がそのまま使える。

```
- [ ] 玄関の向きを決める [家の間取り](/<orgId>/project/<spaceId>/wiki?page=<pageId>)
- [ ] 間取り案を3つ作る（期限: 9/20） [検討メモ](/<orgId>/project/<spaceId>/wiki?page=<pageId>)
```

### 何ができるか

紐づけ先のページに **「仕様書として扱う」（`仕様書` タグ）** が入っているかで、できるタスクが変わる。
これは画面（タスク詳細の「仕様書連携」）と同じ規則。

| リンク先 | できるタスク | 完了できるか |
|---|---|---|
| 「仕様書として扱う」が入っている | **決定事項のタスク**（`type='spec'` / `decision_state='considering'` / `ball='client'`） | 決定するまで完了できない（`enforce_review_gate`） |
| 入っていない | ふつうのタスク（`type='task'` / `status='todo'` / `ball='internal'`） | 止めない。ページは参考資料として紐づく |

### 決まりごと

- 拾うのは **未チェック（`- [ ]`）の行だけ**。`- [x]` は拾わない。
- リンク先は **同じ組織・同じプロジェクトの Wiki ページ**に限る。他所のページ ID を書いた行は無視する。
- 1行に Wiki のリンクが2つあっても、**先頭の1つ**だけを使う（タスクは1行につき1つ）。
- タスクの名前 = 行の文字から、リンクと `<!--task:...-->` の印を取り除いたもの。空ならリンクの表示文字を使う。
  どちらも空の行はタスクを作らない。
- 期限は `期限: M/D` または `期限: YYYY/M/D`。`M/D` は**日本時間の今年**として読み、過ぎていれば来年にする。
- 行末に `<!--task:<uuid>-->` が付いた行は作成済みとして飛ばす（同じ行から二重に作らない）。

## B. 仕様書ファイルのパスで作る（従来・そのまま動く）

```
- [ ] SPEC(/spec/REVIEW_SPEC.md#meeting-minutes): 仕様として決めること（期限: 9/20, 担当: 名前）
```

- `SPEC(...)` の中身は `/spec/<ファイル>#<アンカー>` の形に限る。形が違う行は無視する。
- 開発用の仕様書ファイルを指す書き方で、打ち合わせで使う Wiki ページは指定できない。
  そのため業務の会議では A を使う。
- 作られるタスクは常に決定事項のタスク（`type='spec'` / `decision_state='considering'`）。
- `担当:` は書いても**読まれない**（DB 側の実装に無い。担当は作成後に画面で付ける）。

## CLI / API から作る

画面の会議「タスク化」タブと同じことができる。

```
agentpm minutes taskify --meeting-id <id> --dry-run   # まず候補を見る（作らない）
agentpm minutes taskify --meeting-id <id>             # 作る
```

- 道具用の RPC は `rpc_get_minutes_preview_as` / `rpc_parse_meeting_minutes_as`
  （`20260914124023_minutes_taskify_as.sql`）。本体は `_impl` に出し、画面用は
  `auth.uid()`、道具用は実行者を明示する。`task_events.actor_id` は画面と同じ意味になる。
- **権限の確認は `_actor_can_write_space`**。`app_can_write_space` は中で `auth.uid()` を
  見るので、鍵で動く道具から呼ぶと必ず弾かれる（`20260914100928` で踏んだのと同じ罠）。
- CLI は呼ぶ直前に本文を読み、それをそのまま渡す。DB 側が「渡された本文＝いまの本文」を
  確かめ、違えば何も書かずに止める（隙間に入った他の人・AI秘書の書き込みを消さないため）。

検証は `supabase/tests/run_minutes_taskify_as.sh`（6項目）。

## 実装の場所

| 何 | どこ |
|---|---|
| 行の判定（TS） | `src/lib/minutes/wikiTaskCandidate.ts` |
| 候補の形をそろえる（TS） | `src/lib/minutes/preview.ts` |
| 候補の一覧・作成（SQL） | `rpc_get_minutes_preview` / `rpc_parse_meeting_minutes` |
| 最新の定義 | `supabase/migrations/20260914065219_minutes_taskify_wiki_link.sql` |
| 画面 | `src/components/meeting/MeetingInspector.tsx`（「タスク化」タブ） |

判定に使う正規表現は **TS と SQL の2か所にある**。片方だけ直すと、画面に出る候補一覧と実際に
作られるタスクが食い違う。`src/__tests__/lib/minutes/wikiTaskCandidate.test.ts` が最新の
マイグレーションを探して突き合わせるので、ずれると落ちる。

## 書き込みの歯止め

タスク化は、画面が持っている本文と DB の本文が**同じときだけ**走る。違っていれば何も書かずに
「別の場所で更新されています」で止まる（`HINT=minutes_stale`）。確かめてから書き込むまでの隙間に
入った、ほかの人・AI秘書・CLI の書き込みを消さないため。
