# 導入事例を作るための手順

- **作成日**: 2026-09-18
- **目的**: 事例ページ（`/cases`）を作るための材料を、正しい手順で集める
- **前提**: 中身が1件も無いうちはページを作らない。空の事例ページは、かえって「使われていない」印象を与える

---

## なぜ事例が要るか

B2Bで一番効くのは、同じ業種・同じ規模の会社が使っている事実です。機能の説明を10行足すより、
「10名の制作会社が、報告の時間を月8時間減らした」の1行のほうが刺さります。

ただし**作り話は書けません**。数字も声も、実際のお客様から取る必要があります。

---

## 1. 許諾を取る（ここを飛ばさない）

掲載の範囲を、**書面かメールで**確認します。口頭だけで進めると、あとで揉めます。

| 確認すること | 選択肢 |
|---|---|
| 会社名 | 実名で出す／「東京都・受託開発・10名」のように伏せる |
| 担当者名 | 実名／役職のみ（「制作部 部長」）／出さない |
| 顔写真 | 出す／出さない |
| ロゴ | 出す／出さない |
| 数字 | 実数で出す／「約◯割」に丸める／出さない |
| 掲載場所 | 自社サイトのみ／営業資料にも使う／広告にも使う |
| 取り下げ | いつでも連絡をもらえば取り下げる、と明記する |

**伏せる形でも十分効きます。** 実名が取れないことを理由に事例作りを止めないでください。

---

## 2. 聞くこと

15〜30分で足ります。順番どおりに聞けば、記事の形になります。

### 導入前

1. どんな仕事をされていますか（業種・人数・相手先の数）
2. 導入する前は、何をどう管理していましたか
3. いちばん困っていたのは何ですか
4. それは週にどれくらいの時間でしたか

### 導入後

5. 最初に何から使い始めましたか
6. いま、いちばん使っている機能は何ですか
7. 変わったことを1つ挙げるとしたら何ですか
8. 時間や回数で言うと、どれくらい変わりましたか
9. 相手先（クライアント）の反応はどうでしたか

### 正直なところ

10. 使いにくいと感じるところはありますか
11. 導入するとき、つまずいたところはありますか

> **10番と11番を必ず載せます。** 良いことしか書いていない事例は読まれません。
> 課題が書いてあると、他の項目まで信じてもらえます。

---

## 3. 記事の形

```
見出し    ：お客様の言葉をそのまま1文（「報告のための報告が無くなりました」）
基本情報  ：業種／人数／使っている機能／導入時期
導入前    ：何に困っていたか（3〜4行）
導入後    ：何をどう変えたか（3〜4行）
数字      ：1〜2個だけ。多いと嘘くさくなる
正直な話  ：使いにくいところ、つまずいたところ
```

---

## 4. 集まったら

1. `src/app/cases/page.tsx` を作る（`/screens` と同じ作り。事例の配列を回すだけ）
2. `src/lib/routes/publicPaths.ts` に `'/cases'` を足す（**忘れるとログイン画面に飛ぶ**）
3. `src/app/sitemap.ts` の `STATIC_PATHS` に足す
4. ヘッダーの「活用シーン」とフッターに導線を足す

**1件でもあれば作る価値があります。** 3件揃うまで待たないでください。
